# Risk Specification

## 1. 正式名称と目的

**Decided**：主要指標の正式名称を「耐性基準時損失」とする。

Risk機能は売買推奨ではなく、保有ポジションが指定価格まで下落した場合の損失と、純資産によるカバー状況を把握する判断支援機能である。

## 2. 現在の実装

**Current**：`assets/trade-history-core.js`では、TRY/JPY、HUF/JPY、MXN/JPY、ZAR/JPY、CZK/JPYをコード固定のRisk対象としている。

- HUF/JPY：0.10円時損失
- その他の対象ペア：1.00円時損失
- FX 0円時損失
- 暗号資産0円時損失
- 最大損失：FX 0円時＋暗号資産0円時

**Current**：画面の「FX 1円時損失」には、HUF/JPYの0.10円時損失も合算される。

**Current**：取引履歴が空の場合、固定フォールバック値を表示する。

**Known issue**：現在の暗号資産0円時損失はSBI VC口座の資産額全体を参照するため、JPY現金を含む可能性がある。正式仕様とは異なる。

## 3. Risk対象設定

**Decided**：Risk設定は、ペア単位の設定と個別ポジション単位の設定を概念上分離する。個別ポジション設定はペア設定に対する上書きであり、両者を同じデータとして扱わない。

### ペア単位

- Risk対象ペア
- ペアごとの耐性基準価格

**Planned**：Risk対象ペアとペアごとの耐性基準価格を、将来的にアプリ上から編集可能にする。

初期基準：

| ペア | 初期耐性基準価格 |
|---|---:|
| TRY/JPY | 1.00円 |
| HUF/JPY | 0.10円 |
| その他 | 未設定 |

「未設定」はRisk対象外と同義ではない。基準値がないため自動計算しない状態として扱い、ユーザーに設定要否を示せる余地を持たせる。

### 個別ポジション単位

- Risk対象ON/OFFの上書き
- 将来のRisk対象数量上書き

**Decided**：個別ポジションについて、ペア設定とは別にRisk対象ON/OFFを上書きできるようにする。

**Planned**：個別ポジションのRisk対象数量を、実保有数量とは別に手動で上書きできるようにする。

**Decided**：戦略分類とRisk対象判定を同一視しない。「キャリー」戦略でもRisk対象OFFにでき、別戦略でもRisk対象ONにできる。

## 4. Riskメタデータの分離

**Decided**：取引履歴・Raw Transactionsと、TradeScope独自のRiskメタデータを分離する。

概念例：

```text
PairRiskSetting {
  pairId
  enabled
  tolerancePrice
  updatedAt
}

PositionRiskOverride {
  positionId
  enabledOverride  // nullならペア設定を使用
  quantityOverride // nullなら実ポジション数量を使用
  updatedAt
}
```

**Under consideration**：上記は責務分離を示す概念例であり、ID、継承方法、保存キー等の最終データ構造は未確定である。

**Decided**：CSV/PDF再インポートでRisk設定、戦略、タグ、Memoを失わない。

## 5. 耐性基準時損失

ロングポジションの概念式：

```text
耐性基準時損失
= Σ max(
    (平均建値 - 耐性基準価格)
    × Risk対象数量
    × 通貨単位,
    0
  )
```

- `Risk対象数量`は、数量上書きがあればその値、なければ実ポジション数量。
- FXペアの損益通貨がJPYでない場合は、必要な換算を明示的に行う。
- **Decided**：換算レートが不明な場合は固定値を実レートのように扱わず、計算不能または参考値と明示する。
- **Under consideration**：ショートポジション、クロス通貨、ヘッジポジションの正式式。

## 6. 最大損失

**Decided**：FX 0円時損失は、Risk対象となっているロングFXポジションを0円まで下落させた場合の損失とする。

JPY建てロングポジションの概念式：

```text
FX 0円時損失
= Σ 平均建値 × Risk対象数量 × 通貨単位
```

**Under consideration**：ショートポジションでは0円が最大損失にならない。ショート、クロス通貨、両建て・ヘッジ等の最大損失と換算方法は、正式ルールを別途決定する。

```text
最大損失
= FX 0円時損失
+ 暗号資産0円時損失
```

**Decided**：

- 暗号資産0円時損失には暗号資産の現在評価額のみを含める。
- 暗号資産口座内のJPY現金を含めない。
- 株式、ETF、投資信託等は、このRiskセクションの最大損失に含めない。
- 0円時損失は損失額を正数で表す。

## 7. Risk状態

```text
耐性カバー率 = 純資産 ÷ 耐性基準時損失 × 100
```

判定順序：

| 状態 | 条件 |
|---|---|
| 最大耐性 | 純資産 >= 最大損失 |
| 基準耐性 | 純資産 >= 耐性基準時損失 |
| 適正 | 耐性カバー率 >= 85% かつ 100%未満 |
| 注意 | 耐性カバー率 >= 70% かつ 85%未満 |
| 警告 | 耐性カバー率 < 70% |

**Decided**：最大耐性・基準耐性は比率区分より優先して表示する。

**Planned**：85%と70%の閾値を、将来的にアプリの設定から変更可能にする。

**Decided**：耐性基準時損失が0の場合、耐性カバー率を無限大や0%と表示せず、「対象Riskなし」等の明示状態とする。具体的な文言はUI設計時に決定する。

## 8. 「完了」の扱い

**Decided**：累積スワップが耐性基準時損失を上回る「完了」という考え方は、投資方針上の参考概念として残す。

**Decided**：これはTradeScopeのRiskステータスには組み込まない。また、別の分析指標としても現時点ではアプリへ組み込まない。

## 9. 0円耐性との二軸表示

耐性状態とは別に、以下を正式表示項目とする。

```text
0円耐性カバー率 = 純資産 ÷ 最大損失 × 100
```

```text
0円時未カバー額 = max(最大損失 - 純資産, 0)
```

**Decided**：最大損失が0の場合は「対象Riskなし」等とし、除算結果を誤解させない。

## 10. 口座別Risk

**Decided**：全体の耐性判定と、各FX口座のロスカット耐性を分離する。

**Current**：月次データに`maintenanceRate`が存在するが、現行トップのRisk状態判定には統合されていない。

**Planned**：CSV等から必要データを取得できる段階で、GMO、LIGHT FX、みんなのFX等について口座別証拠金維持率を表示する。

**Under consideration**：各社固有のロスカットルール、必要証拠金、評価損益、注文中証拠金等の正規化方法。

## 11. What-ifシミュレーション

**Planned**：実データを変更せずに、追加投資を仮定したRisk変化を表示する。

入力候補：

- ペア
- 追加口座
- 追加価格
- 追加数量

出力候補：

- 追加後平均建値
- 追加後耐性基準時損失
- 追加後最大損失
- 追加後耐性カバー率
- 追加後0円耐性カバー率
- Risk状態の変化

**Decided**：What-ifシミュレーションは常に非破壊とし、正本データ、取引履歴、保有ポジションを変更しない。シミュレーション結果を確定取引へ変換する操作は設けない。

**Decided**：実際の取引データの追加・変更は、手入力、CSV、API等の正式な取引入力フローからのみ行う。

**Decided**：売買推奨機能ではなく、追加した場合のRisk変化を表示する判断支援機能とする。

## 12. 現行実装との差異

- 対象ペアがコード固定で、アプリから編集できない。
- 正式初期基準ではTRY/HUF以外は未設定だが、現行はMXN/ZAR/CZKも1円基準で自動対象になる。
- Risk対象ON/OFF、数量上書き、独立Riskメタデータがない。
- 耐性カバー率、Risk状態、0円耐性カバー率、未カバー額が未実装。
- 暗号資産0円時損失からJPY現金を除く保証がない。
- 取引履歴がない場合に固定Risk値が表示される。
